## 3. Decisiones visuales

Carbon neutro como base oscura; blanco neutro como base clara. Laton para
acciones principales y verde para apoyo/foco. Rojo, ambar y azul solo tienen
funciones semanticas. La calidez procede de la tipografia, los acentos y la
fotografia, no de llenar todas las superficies de marron o crema.

Tras la revision del usuario, Archivo sustituye Instrument Serif y Plus
Jakarta Sans en toda la interfaz. Los titulos usan Archivo Condensed semibold
y una escala mas compacta; el cuerpo y los controles usan Archivo de ancho
normal y conservan sus tamanos y alturas de lectura. La variante condensada
permite leer palabras largas de las muestras al 200 % en 320 px sin partirlas
por dentro. Sin reducir el escalado accesible, tracking
negativo ni fuentes que cambian de tamano segun el ancho del viewport.

El unico identificador visual de marca es el logo original: `FudiLogo` reutiliza
el PNG sin redibujarlo ni reconstruirlo con una fuente. Se elimina el segundo
FUDI del catalogo y la marca tipografica de la pantalla provisional. El titulo
del catalogo pasa a ser Sistema visual; el pie solo identifica la tarea interna.

Secciones sin marcos ni cards anidadas. Cards a 8 px; radios mayores solo en
paneles modales o muestras del token. Sombras muy limitadas. Sin glassmorphism,
gradientes decorativos, animaciones de entrada ni shimmer.

## 7. Variantes y estados

| Componente | API y estados |
| --- | --- |
| FudiButton | primary/secondary/ghost/destructive; small/medium/large; normal, hover, pressed, focused, disabled, loading; icono y expanded opcionales |
| FudiIconButton | normal/selected/disabled; tooltip obligatorio mediante label; focusNode opcional |
| FudiCard | surface/muted/elevated; padding configurable; onTap y semanticLabel opcionales |
| FudiInput | label, placeholder, helper, error; enabled; controller o initialValue; prefix/suffix; password; multiline; validator/Form, autofill y submit |
| FudiSearchField | controller propio o externo; escritura, submit y borrado; disabled; sin busqueda real |
| FudiChip | seleccionado/no; disabled; neutral/success/warning/error/info; filtro con callback o estado informativo sin accion |
| FudiAvatar | ImageProvider, fallback personalizado, iniciales por grafema o icono; tamanos configurables; fallback ante error de imagen |
| FudiDivider | horizontal/vertical; espaciado configurable; rol de color consistente |
| FudiSkeleton | rectangulo/circulo; dimensiones y label; estatico y ligero |
| FudiEmptyState | icono, titulo, descripcion; accion opcional |
| FudiErrorState | titulo/mensaje/retryLabel opcionales; retry opcional; generico localizado, sin mapear AppFailure |
| FudiBottomSheet | titulo y contenido; `show<T>`; dismissal/drag configurables; scroll, safe area, teclado y boton de cierre |

La reserva de icono/spinner y del foco evita cambios de geometria en botones.
Los inputs conservan el grosor del borde y reservan una linea de helper.
Las validaciones largas pueden aumentar altura: no se recortan para imponer
una falsa altura fija. Los placeholders y etiquetas pueden ocupar varias lineas.

## 8. API publica

Unico import recomendado para futuras features:

```dart
import 'package:fudi/design_system/design_system.dart';

FudiButton(
  label: strings.continuar,
  icon: LucideIcons.arrowRight,
  loading: state.isSubmitting,
  onPressed: state.canSubmit ? submit : null,
);

FudiInput(
  label: strings.nombre,
  controller: nameController,
  helper: strings.opcional,
  validator: validateName,
);
```

Ejemplo conceptual: las strings y el estado pertenecen al consumidor, no al
Design System. Lucide se importa desde su paquete aprobado. El barrel exporta
primitivas, FudiLogo, enums, tokens, tema y motion; no exporta catalogo, FocusFrame ni
registro de licencias. El consumidor ofrece los delegates de localizacion de
FudiApp y un FudiTheme, y sigue siendo responsable de controllers y callbacks.

## 20. Riesgos visuales o tecnicos

- Falta validar en dispositivos Android/iOS reales, teclado virtual y lectores
  de pantalla nativos. Web/widget tests no equivalen a esa validacion.
- La paleta esta comprobada para sus combinaciones actuales; nuevas superficies,
  opacidades y texto sobre fotografias exigiran nuevas comprobaciones.
- La opcion de compilacion permite incluir el catalogo en release por decision
  explicita: no usarla en el comando de distribucion.
- La ruta se excluye por defecto, no sus assets declarados en pubspec. La foto
  de muestra permanece en el bundle; optimizar ese empaquetado queda pendiente.
- El motor web CanvasKit conserva el CDN predeterminado de Flutter. Las fuentes
  estan locales, pero el modo totalmente offline del motor queda fuera de alcance.
- La foto de muestra y el logo provienen del legado; sus derechos originales
  de distribucion no pueden deducirse solo de estar en el repositorio.
- No se evaluaron cargas remotas de imagenes ni pantallas de producto. La
  tarjeta fotografica del catalogo no establece una RestaurantCard futura.
- Los ajustes locales del contrato y LocalDateTime siguen como riesgos de
  MIG-001 para las fases correspondientes; esta tarea no los modifica.

Autocritica Hallmark basada en las capturas: filosofia 4, jerarquia 4, ejecucion
4, especificidad 4, contencion 5, variedad 4. La identidad gastronomica deriva
de fotografia clara, contraste, logo original y jerarquia tipografica; el catalogo sigue siendo
una herramienta y no establece un layout de producto. No se asigna perfeccion:
falta validar en hardware nativo y con contenido de features reales.

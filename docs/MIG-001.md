## 5. Discrepancias y decisiones

| Hallazgo | Evidencia y tratamiento |
| --- | --- |
| YAML declara `www.fudi.es` como principal y `api.fudi.es` como alternativo/legacy | Angular produccion, proxy JS activo y scripts backend usan `api.fudi.es`. Se mantiene AppConfig, sin cambiar produccion por el YAML. |
| Proxy Angular JSON local frente a JS de QA remoto | `angular.json` usa `proxy.conf.js`, cuyo destino es produccion; `proxy.conf.json` apunta a localhost. Flutter conserva un desarrollo local explicito, sin copiar ese proxy remoto. |
| Tres errores de sintaxis de contrato | Descripciones de respuestas 400 con comas sin comillas generan tres claves inesperadas en PUT administrativos de recomendaciones. Se permite solo ese conjunto auditado al parsear; el contrato preparado supera validacion estricta. |
| Falta `RestaurantPublic.slug` | Existe en RestaurantPublicDTO y Angular. Se anade al contrato local. |
| Request de POST reserva incompleto | BookingCreateRequest y Angular incluyen `observations` e `interior`. Se incorporan, con maxLength 1000 para observations. |
| GET publico reserva tipado como DTO privado | Java devuelve BookingPublicDTO; YAML y Angular declaran BookingCustomer. Se genera BookingPublic con los campos publicos reales. |
| POST reserva, wrapper frente a DTO | Java devuelve BookingCustomerDTO directo con 201; OpenAPI coincide. Angular acepta tambien un wrapper alternativo. No se inventa un wrapper para Flutter. |
| Enum antiguo de Menu.restaurantType | Java usa 32 valores ingleses de RestaurantType; YAML contiene valores espanoles antiguos. Se actualiza la enum local. |
| Herencia allOf de RecommendationAdmin | Los records Java son independientes y la lista administrativa usa otro DTO. dart-dio falla en imports al heredar la lista publica. Se aplanan las propiedades, con override administrativo de restaurants. |
| LocalDateTime Java frente al serializer UTC estandar | Iso8601DateTimeSerializer hace parse(...).toUtc() y atribuye la zona del dispositivo a timestamps sin offset. WireDateTimeSerializer sustituye solo ese serializer en la integracion: conserva hora civil sin offset y respeta instantes con offset. |
| Login/registro no estan en AuthController | Existen en UserController bajo `/api/v1/auth/login` y `/register`; la duda de MIG-000 queda resuelta. AuthController gestiona Google, refresh, logout y contrasenas. |
| Google: Angular declara `userId` | AuthResponse Java y OpenAPI usan `id`. No se modifica Angular ni se construye sesion Flutter. |
| PUT users/me usa schema generico User | Java recibe UserAccountUpdateRequest, distinto de UserMeDTO de salida. No se utiliza ese PUT en MIG-001; se debe auditar su contrato al migrar Account. |
| Errores heterogeneos | Formato general status/error/message/path, validacion errors por campo, reservas error/code. Se mantiene el mapper tolerante de MIG-000; no se introduce un DTO de error universal. |
| Parametros de token publicos | Java acepta t/ct como opcionales en el binding; el acceso de negocio exige firma valida. Se conserva su obligatoriedad en el contrato de cliente, sin inventar acceso anonimo sin firma. |

## 11. Integracion Dio

`lib/core/network/generated_api_client.dart` aporta dos providers y una
frontera tecnica sin logica de producto:

```text
AppConfig -> dioProvider -> fudiApiProvider -> GeneratedApiClient
                                      ApiClient / mapNetworkError -> AppFailure
```

FudiApi recibe el mismo objeto Dio de MIG-000 y `interceptors: const []`.
Asi no instala por defecto OAuth/basic/Bearer/API-key ni cambia origen o
timeouts. El cierre sigue siendo propiedad de dioProvider.
La lista de serializers generados se reutiliza con una unica sustitucion
manual: `WireDateTimeSerializer`, para no transformar implicitamente
LocalDateTime Java en UTC. Serializa valores civiles sin Z y valores UTC
con Z; offsets explicitos se interpretan como instantes. No se modifican
serializers generados ni DTOs. Usar directamente standardSerializers fuera
de la integracion recuperaria la conversion UTC original del generador.
`execute` devuelve DTO no nulo; una respuesta vacia inesperada produce
AppFailure. `executeVoid` acepta respuestas de operaciones sin cuerpo.
Ambas pasan por ApiClient y convierten DioException y fallos internos de
serializacion antes de llegar a futuras features. Solo futuras capas de
datos deben usar esta frontera, nunca widgets ni llamadas directas de UI.

## 21. Riesgos y limites

- No se auditan todas las operaciones. Cada feature debe contrastar sus
  endpoints contra Java antes de consumirlos, especialmente requests genericos.
- El contrato preparado es una correccion local explicita, no una nueva API.
  Backend debe reconciliar su OpenAPI en una tarea propia; no se modifica aqui.
- DateTime de Dart y LocalDateTime Java tienen distinta semantica temporal:
  algunos timestamps no traen offset. La politica conserva su hora civil
  en lugar de convertirla implicitamente a UTC. Un DateTime civil de Dart
  sigue teniendo marca local y no define el instante o zona del restaurante;
  cada feature debera confirmar zona de
  restaurante/mercado antes de mostrar o enviar instantes; no asumir UTC.
- Un fallback de enum evita romper el parseo, no autoriza acciones desconocidas.
  Debe tratarse conservadoramente en la logica de negocio futura.
- oneOf de recomendaciones requiere seleccionar lista/pagina en su futura
  capa de datos; no se crea RecommendationRepository ni se oculta esa union.
- Auth generado no equivale a sesion usable. No existe almacenamiento seguro,
  refresh, politica de cookies ni interceptor JWT activado.
- CORS web conserva los limites de MIG-000 (localhost:5173 permitido; no
  anadir Accept-Language/X-CorrelationId no permitidos). No se prueba CORS
  con memoria. No se accede a un backend vivo ni a produccion.
- La regeneracion requiere fuente backend accesible, Java y acceso a Maven/pub
  la primera vez. El paquete versionado permite flutter pub get sin codegen.
- Actualizar generador/builders/plantillas exige repetir el diff y las pruebas.
  Los avisos mecanicos silenciados solo afectan al paquete generado.
- Se valida build web; no se afirma compilacion iOS en Windows ni release
  Android firmado. No se prueban capacidades nativas de producto.

## 22. Auth aplazado deliberadamente

OpenAPI define HTTP Bearer con bearerFormat JWT; el access token se devuelve
como Token.token en login/refresh y AuthResponse.token en Google.
UserController hace login y registro; AuthController Google, refresh, logout.
AuthSessionService establece fudi_refresh_token HttpOnly con path /api/v1/auth:
local Secure=false/SameSite=Lax, produccion Secure=true/SameSite=None,
configurable por propiedades. Refresh lee la cookie y renueva access token;
logout revoca la sesion y elimina la cookie. No se infiere un protocolo mobile
equivalente sin revisar sus necesidades.

Angular guarda jwt_token en localStorage, adjunta Bearer, hace refresh y
logout con withCredentials y coordina reintentos 401. No se traslada ese
almacenamiento ni esos interceptores a Flutter. El soporte Bearer generado
se conserva dentro del paquete, pero no se registra en el Dio de aplicacion.
MIG-020 resolvera login/registro/Google, secure storage, Keychain/Keystore,
refresh automatico, cookies, concurrencia y ciclo de sesion nativa.
